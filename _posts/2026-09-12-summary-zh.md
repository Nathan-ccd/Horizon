## [美国环保署计划取消数据中心污染许可的公众审查](https://capitalbnews.org/data-centers-permit-rules-epa/) ⭐️ 8.0/10

美国环保署（EPA）计划取消一项联邦要求，即各州在批准工业设施（包括快速增多的数据中心及其供电电厂）的空气污染许可前，必须通知公众并允许公众发表意见。该提案由 Capital B News 和 Truthout 报道，已引发环保倡导者的强烈批评。 这一撤销将移除社区对数据中心许可提出质疑或施加影响的关键渠道，而数据中心正为满足 AI 算力需求快速扩张，且常选址于居民区附近。在数据中心能耗和相关空气污染激增之际，此举可能削弱环境监管，影响当地公众健康以及人们对监管程序的信任。 该变更针对的是新源审查（NSR）许可程序中针对小型排放源的公众参与要求，意味着各州在发放许可前将不再有联邦义务通知公众或接受公众意见。该规则将广泛适用于工业设施，而不仅限于数据中心，并且出台之际 EPA 已因预算和人员削减而被大幅削弱。

## [单张 GPU 从零训练 2.1 亿参数文生图 DiT](https://www.reddit.com/r/MachineLearning/comments/1wdfmvq/training_a_210m_texttoimage_dit_from_scratch_on/) ⭐️ 8.0/10

一位开发者用单张 RTX PRO 6000 GPU 在 3.5 天内从零训练了一个 2.1 亿参数的文生图扩散 Transformer，使用 420 万张 256²分辨率图像，并报告了三项此前很少被明确说明的测量结果：学习到的空注意力槽吸收了约 90%的交叉注意力质量、流匹配损失是健康信号而非质量信号、训练时的时步偏移比将采样步数翻倍更有价值。 这项工作表明，有意义的文生图扩散研究在单张接近消费级的 GPU 上即可完成，降低了独立研究者的门槛；其关于空注意力槽和时步偏移的发现，也可能为整个扩散生态中更高效的训练与采样方案提供参考。 该模型采用交叉注意力 DiT（896 维、16 个块），结合 2D RoPE、QK-norm、SwiGLU、adaLN-single，使用带 logit-normal 时步的整流流，并采用由 SD3/RAE 规则为 32 通道 FLUX.2 潜变量推导出的 2.8 偏移；训练批大小为 256、共 40 万步，EMA 为 0.9999，torch.compile 带来 2.4 倍加速，最终模型在 2456 条留出提示上取得 FID 27.0 和 90%的基于检测器的物体准确率。

reddit · r/MachineLearning · /u/IvanMikhnenkov · 9月11日 13:00

**背景**: 扩散 Transformer（DiT）用 Transformer 替代扩散模型中的 U-Net 主干，能随算力良好扩展，已成为 FLUX、Stable Diffusion 3 等最先进图像生成器的基础。流匹配是一种训练目标，学习将噪声输运到数据的速度场，其损失值反映的是模型对目标的拟合程度，而非生成图像的质量。寄存器 token 是添加到 Transformer 输入序列中的额外可学习 token，充当全局暂存区，这一技术最初用于修复视觉 Transformer 中的高范数伪影。

## [Python 3.15 软弃用 re.match()，改用 re.prefixmatch()](https://simonwillison.net/2026/Sep/11/soft-deprecating-re-match/) ⭐️ 6.0/10

预计于 2026 年 10 月发布的 Python 3.15 软弃用了长期存在的 re.match() 函数，并引入了行为完全一致但语义更清晰的别名 re.prefixmatch()。这一改动由 Python 3.15 发布经理 Hugo van Kemenade 说明，他指出 re.match() 只锚定字符串开头，而不锚定结尾。 re.match() 是 Python 标准库中最容易被误解的函数之一，为它取一个能自我说明的名字可以减少开发者常犯的错误。由于这是软弃用，现有代码仍可正常运行，但新代码和代码检查工具会逐渐引导人们改用 re.prefixmatch()、re.search() 或 re.fullmatch()。 re.prefixmatch() 和 re.Pattern.prefixmatch() 是 re.match() 和 re.Pattern.match() 的完全同义词，行为完全相同，包括只匹配前缀而非整个字符串。软弃用意味着该 API 被标记为“不应再用于编写新代码”，但并不承诺或威胁未来会将其移除。

rss · Simon Willison · 9月11日 14:47

**背景**: 在 Python 的 re 模块中，re.match() 只在字符串开头检查匹配，re.search() 在字符串任意位置检查匹配，而 re.fullmatch() 要求整个字符串都匹配。这一细微差别困扰了多代 Python 开发者，许多人误以为 match() 的行为与 search() 相同。Python 的软弃用概念在 PEP 387 的讨论中得以明确，它允许标准库在新代码中不鼓励使用某个 API，而不安排将其移除，从而避免硬弃用带来的破坏性。
